### 🎯 1. ARCHITECTURAL CONSTRAINTS & CORE RULES

1. **Zero Bespoke CSS & Zero Hex Hardcoding:**
   - All colors MUST be defined once as OKLCH tokens in `src/styles.css` and consumed via Tailwind CSS v4 `@theme inline` utilities.
   - Never write raw hex values (e.g., `#007acc`), raw OKLCH values, or arbitrary Tailwind classes (e.g., `bg-[#1a1a1a]`) inside component files.

2. **Contrast & The `-text` Alias Rule (WCAG 2.1 AA):**
   - Every vivid accent token MUST have a paired high-contrast `-text` alias token for light theme rendering.
   - Light theme `-text` tokens must measure $\ge 4.5:1$ against `--background` and `--card`.
   - In `.dark`, `-text` tokens point directly back to the vivid accent tokens.

3. **The Density Contract (4px Grid):**
   - **Comfortable Density (Default):** All interactive daily surfaces MUST use `h-11` (44px target), `py-3`, `gap-3`.
   - **Compact Density (Audit/Backlog Only):** Data-dense views use `h-8`, `py-1`, `gap-1.5`.
   - **Rule:** Density toggles MUST ONLY swap 4px grid multipliers on the same component—NEVER fork or duplicate components for dense variants.

4. **Component Isolation (CVA + shadcn Patterns):**
   - Build all atomic components using `class-variance-authority` (cva), `clsx`, and `tailwind-merge`.
   - All interactive elements must enforce `focus-visible:ring-2`, keyboard accessibility (Space/Enter), and `motion-reduce:transition-none`.

5. **Middle-Layer Architecture:**
   - Components MUST remain strictly presentational (render props, emit callbacks).
   - Side effects, state persistence, local storage, and simulation feeds MUST be encapsulated in custom React hooks in `src/lib/`.
